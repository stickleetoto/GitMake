GitMake v1.2.4 + AI/MCP

ONE-CLICK CLAUDE SETUP
  gitmake ai setup

Enable reviewed write/apply tools:
  gitmake ai setup --write

Status:
  gitmake ai status

NORMAL AI PUBLISH WORKFLOW
1. Ask Claude to publish/upload/create/update the current project folder or ZIP.
2. Claude should call `gitmake_publish` first.
3. GitMake prepares and surfaces the reviewed plan.
4. GitMake requests human approval through the MCP client UI.
5. After approval, GitMake revalidates the exact reviewed plan and applies it.
6. The same logical publish operation returns the final repository/release result.

Do not stop the chat merely to ask for approval when `gitmake_publish` and MCP elicitation are available. Never auto-accept the human approval dialog.

PLAN-ONLY WORKFLOW
Use `gitmake_prepare` when the user explicitly asks to inspect/prepare a plan without publishing.

COMPATIBILITY FALLBACK
If the MCP client cannot perform elicitation:
  gitmake_prepare
  gitmake approve
  gitmake_apply(plan_id)

There is no normal approval token to copy/paste in the v1 flow. The local fallback grant is short-lived, single-use, and bound to the exact reviewed plan.

Destructive terminal fallback:
  gitmake approve --destructive

Read-only MCP remains the default. GitMake never exposes a tool that can create its own human approval grant without a client-controlled human response or terminal approval.

Generic MCP descriptor:
  gitmake ai setup --client generic --json
