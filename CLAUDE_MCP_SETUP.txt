GitMake v0.7.3 + AI/MCP
=======================

CLAUDE CODE (recommended one-click path)

  gitmake ai setup

This:
  - detects Claude Code
  - ensures a stable GitMake executable path
  - registers the user-scoped stdio MCP server
  - defaults to read-only tools
  - checks connection status

To expose guarded config-write + approved-plan apply tools:

  gitmake ai setup --write

Actual MCP apply still requires a one-shot human approval token:

  gitmake plan --json
  gitmake approve <plan_id>

The approval command requires an interactive terminal. MCP does not expose a tool that can create its own approval token.

GENERIC MCP CLIENTS

  gitmake ai setup --client generic --json

GitMake returns a machine-readable stdio descriptor containing the executable path and MCP arguments. It does not edit an unknown client's config automatically.

RAW SERVER

Read-only:
  gitmake mcp

Guarded write surface:
  gitmake mcp --allow-write

GitMake's MCP surface intentionally covers project inspection, discovery, schema/config handling, preview, plan, history, and approved apply. It does not expose force push, repository deletion, history rewrite, or an unreviewed direct-publish tool.

HIGH-LEVEL PREPARE (v0.7.3)

For ZIP-only or unconfigured projects, prefer the MCP tool:

  gitmake_prepare

It performs discovery -> config inference/validation -> security/preflight -> identity/risk -> reviewed plan in one call.

In default read-only mode, missing gitmake.json stays in memory. Do NOT use Claude Write/Edit to create gitmake.json when gitmake_prepare or gitmake_config_write is available.

With `gitmake ai setup --write`, gitmake_prepare may persist a missing config through GitMake's atomic writer, but it still stops before apply.
